## 2쪽 — 문제 정의 (안전강화 공익성)

*겨냥: 활용성 30점 중 공익성*

**농업용수는 부족을 알고 나서는 늦다.**

- 저수율 데이터는 이미 공개돼 있다. 그런데 공개된 형태는 숫자와 그래프여서, 정작 물을
  대는 농업인이 **"지금 물을 대도 되는지"**를 판단하기 어렵다.
- 공식 가뭄 정보(논가뭄지도)는 **연 1회 공표**다. 오늘 날짜의 시군 값이 비어 있는 날이
  대부분이고, 가뭄예경보는 월 단위·광역 단위여서 내 저수지 사정과 어긋난다.
- 가뭄 대응은 **미리 해야 효과가 있다.** 관개 순번 조정, 논물 걸러대기, 용수 절감은
  단계가 나빠진 뒤가 아니라 나빠지기 전에 시작해야 한다.
- 주 사용자가 고령 농업인이다. 작은 글씨, 전문 용어, 로그인 절차가 그대로 진입 장벽이 된다.

**그래서 수신호는 세 가지를 한다.**

| 문제 | 수신호의 답 |
|---|---|
| 오늘 값이 없다 | 저수지 실측 수위로 오늘의 지역 값을 추정하고, 추정임을 화면에 밝힌다 |
| 숫자만 있다 | 다음 단계 도달 시점을 계산해 "며칠 뒤"가 아니라 날짜로 보여준다 |
| 무엇을 할지 모른다 | 단계별 행동 3가지를 쉬운 문장으로 제시한다 |

**공익성** — 개인 이익이 아니라 지역 용수 안전이다. 회원가입·과금이 없고, 대표 저수지
단위 정보라 수리계·지사가 같은 화면을 근거로 대화할 수 있다.

## 3쪽 — 서비스 개요와 핵심 화면

*겨냥: 완성도 10점*

**사용 흐름 (로그인 없음)**

```
스플래시 → 온보딩(3장) → 약관 동의 → 주소 검색 또는 저수지 이름 검색
        → 우리 지역 대표 저수지 등록 → 메인 → 흐름 상세
```

**메인 화면 구성** 〔화면 캡처 3장: 메인 / 흐름 상세 / 지역 설정〕

| 순서 | 카드 | 보여주는 것 |
|---|---|---|
| ① | 오늘 우리 저수지 | 대표 저수지 실측 저수율(원저수율 %)과 지역 평년 대비 값, 공식 가뭄 단계 게이지 |
| ② | 이 추세라면 | 다음 단계 도달 예상 시점(날짜)과 추세 방향 |
| ③ | 저수율 흐름 | 실측 30일 + 예측 30일 그래프. 지역 평년 대비 / 저수지 실측 / 함께 보기 3가지 지표 전환 |
| ④ | 수신호 코치 | 오늘 할 일 3가지 |
| ⑤ | 주변 지역 비교 | 같은 시·도 안에서 우리 지역 위치 |
| ⑥ | 근거·한계 | 사용한 데이터 원천, 기준 시각, 추정 여부와 검증 오차 |

**고령 사용자 배려**

- 회원가입·로그인·알림 권한 요청 없음. 기기에 저장하는 것은 코드 2개(시군·저수지)뿐.
- 모든 문구를 ~해요체 짧은 문장으로. "예측", "확률" 같은 단정 표현 대신 "보여요".
- 명도 대비는 WCAG AA 기준을 만족하도록 단계 색을 **그래픽용·글자용으로 분리**했다.
- 큰 글꼴 1.3배, 스크린리더(TalkBack), OS 애니메이션 삭제 설정을 지원한다.
- 통신이 끊겨도 마지막으로 받은 화면을 유지하고 "언제 받은 정보인지"를 함께 적는다.

저장하지 않는다.

**결합이 만들어 내는 값**

- 데이터 5번으로 **주소 → 우리 지역 대표 저수지**를 정한다. 넓은 시군에서는 읍·면·동·리

- 데이터 1번(오늘 실측)과 3번(공식 평년·단계)을 잇는다. 3번이 연 1회 공표라 오늘 값이

## 5쪽 — AI ①: 예측 모델과 백테스트

*겨냥: AI활용성 20점 — 재현 가능한 백테스트, 오차 공개*
*출처: `data/backtest-report.json`, `docs/prediction-model.md`*

**모델을 고르지 않고 비교했다.** 후보 5종을 같은 조건으로 평가했다.

| 모델 | 7일 MAE | 14일 MAE | 30일 MAE |
|---|---:|---:|---:|
| **naive (채택)** | **1.8493** | **3.0463** | **4.3201** |
| 감쇠추세(damped) | 2.2156 | 3.4536 | 4.7857 |
| 지수평활(ses) | 2.3209 | 3.4152 | 4.5889 |
| 이동평균 7일(ma7) | 2.4938 | 3.5603 | 4.7056 |
| 선형회귀(linear) | 3.3464 | 5.2300 | 8.7553 |

단위는 %p(평년 대비 저수율의 절대오차). 채택 규칙은 **14일 MAE 최저**이며, 2위와의 차가
0.3689%p로 동률 규칙(0.05%p) 적용 대상이 아니다.

**평가 방법 (rolling-origin backtest)**

| 항목 | 값 |
|---|---|
| 대상 | 154개 시군 |
| 기준 시점(origin) | 770개 (시군당 5개, 14일 간격) |
| 표본 | 23,100개 |
| 예측 지평 | 30일 |
| 원천 | 논가뭄지도 `한국농어촌공사_논가뭄지도_20251231.csv` |

**재현 가능성** — `pnpm backtest`를 다시 실행하면 같은 수치가 나온다. 리포트에 원천
파일명과 **체크섬**, 실행 시각, 커밋 해시, 모델 상수를 함께 커밋했다. CI가 문서·계약·
예시의 수치가 리포트와 어긋나면 실패한다.

**오차를 숨기지 않는다** — 화면에 "7일 ±1.8%p, 14일 ±3.0%p"를 그대로 적고, 예측 구간은
잔차 분위수(25~75%)로 띠를 그려 불확실성을 함께 보여준다.

**다음 단계 도달 시점 산식** (선형 외삽, 참고 표현 전용)

```
남은 일수 = ceil( (현재 평년대비 − 목표 단계 임계) / 일일 변화량 )
예) 68%, −0.45%p/일, 목표 60% → 18일    46%, −0.67%p/일, 목표 40% → 9일
```

## 6쪽 — AI ②: 오늘의 지역 값 추정

*겨냥: AI활용성 20점 · 창의성 20점*
*출처: `data/snapshots/region-estimator.json`, `docs/data-sources.md:181`*

**문제** 논가뭄지도는 연 1회 공표(최신 2025-12-31)다. 그대로 쓰면 사용자는 오늘 화면에서
반년 전 값을 보게 된다.

**접근** 저수지 실측 수위로 같은 값을 다시 만든다. 단, **정확도를 검증한 지역에만 쓴다.**

```
통합저수율(시군, d) = Σ(저수율ᵢ(d) × 유효저수량ᵢ) / Σ(유효저수량ᵢ) × 보정계수
평년 대비(시군, d)  = 통합저수율(시군, d) ÷ 평년(시군, d의 월-일) × 100
```

**과신을 막기 위해 구간을 시간순으로 3분할했다.**

| 구간 | 기간 | 쓰임 |
|---|---|---|
| 학습 | 2025-01-01 ~ 08-31 | 보정계수 적합 (여기까지만) |
| 검증 | 2025-09-01 ~ 10-31 | **게이트 판정 전용** |
| 시험 | 2025-11-01 ~ 12-31 | 성능 보고 전용 |

같은 구간에서 계수를 맞추고 성능까지 보고하면 좋아 보일 수밖에 없다. 실제로 검증 구간을
나눠 보니 **학습 구간만으로는 통과했던 13개 지역이 홀드아웃에서 탈락**했다.

**결과**

| 항목 | 값 |
|---|---|
| 후보 시군 | 114곳 |
| 게이트 통과 | **70곳** |
| 홀드아웃 표본 | 4,270개 |
| 홀드아웃 MAE | **0.7394 %p** |
| 중위 오차 | 0.3543 %p |
| 90분위 오차 | 1.875 %p |
| **가뭄 단계 일치율** | **100%** |

**정직한 표기** — 추정으로 채운 날은 화면에 "저수지 실측으로 계산한 값"임을 밝히고, 그
지역의 검증 오차와 사용한 저수지 수·용량 비중을 함께 적는다. 게이트를 통과하지 못한
44개 시군에는 추정을 적용하지 않고 공표값 기준일을 그대로 보여준다.

## 7쪽 — AI ③: 제한형 LLM 코치와 정적 폴백

*겨냥: AI활용성 20점 — 제한형 LLM과 정적 폴백*
*출처: `docs/llm-coach.md`, `apps/web/src/lib/coach/`*

**설계 원칙: LLM에게 판단을 맡기지 않는다.**

| 구분 | 담당 |
|---|---|
| 가뭄 단계, 저수율, 도달 시점, 행동 3가지의 **선택과 순서** | **서버가 확정** |
| 그 사실을 고령 사용자가 읽기 쉬운 문장으로 바꾸는 일 | LLM |

행동은 미리 검증된 카탈로그(공인 단계 5종 × 3개)에서만 고른다. LLM이 카탈로그에 없는
행동을 만들거나 숫자를 바꾸면 **의미 검증에서 걸러 폐기**한다.

**어떤 실패에서도 화면이 깨지지 않는다.** 아래 사유는 모두 HTTP 200 + 행동 3개를 유지한다.

```
disabled · cache_unavailable · budget_exceeded · daily_limit ·
generation_in_progress · timeout · rate_limited · provider_error ·
refusal · max_tokens · validation_failed
```

응답에 `mode`(static / cache / llm)와 `fallbackReason`을 실어 **어느 경로로 만들어졌는지
사용자와 운영자가 함께 확인**할 수 있다.

**비용·남용 통제**

| 가드 | 값 |
|---|---|
| 공모전 종료까지 누적 API 상한 | USD 5 |
| 일일 신규 생성 상한 (KST) | 20회 |
| 검증 통과 응답 캐시 | 30일 |
| 동시 생성 방지 | 생성 lock (TTL 15초) |
| 공개 API 속도 제한 | 코치 20회/분, 주소 검색 30회/분 |

**개인정보를 LLM에 보내지 않는다.** 전달하는 것은 단계·계절·구간 같은 **비식별 값**뿐이다.
주소 원문, 지역 이름, 등록 지역 목록, IP, 기기 ID는 프롬프트와 로그 어디에도 넣지 않는다.
캐시 키 자체를 비식별로 설계해 지역을 역추적할 수 없다.

---

## 8쪽 — 창의성: 조회를 넘어 행동으로

*겨냥: 창의성 20점*

**기존 서비스가 멈추는 곳에서 한 걸음 더 간다.**

| 단계 | 기존 공개 서비스 | 수신호 |
|---|---|---|
| 현재 | 저수율 숫자·그래프 | 같음 (단, 오늘 값을 추정으로 채움) |
| 흐름 | — | 30일 예측 + 불확실 구간 |
| **시점** | — | **다음 단계 도달 예상 날짜** |
| **행동** | — | **오늘 할 일 3가지** |
| 근거 | — | 사용 데이터·기준일·검증 오차·한계 명시 |

**시점을 알려주는 것이 핵심이다.** "지금 관심 단계"는 행동을 바꾸지 않지만, "이 추세가
이어지면 18일 뒤 주의 단계"는 관개 순번 조정을 지금 시작할 이유가 된다.

**세 가지 지표를 함께 보는 그래프** — 지역 평년 대비 예측 / 대표 저수지 실측 / 두 가지를
겹쳐 보기. 지역 단위 공식 지표와 내 저수지 실측이 어긋날 때 그 차이를 눈으로 확인할 수
있다. 두 값은 단위가 달라 축을 따로 두고 각각 눈금을 표시했다.

**정직함을 기능으로 넣었다.** 예측이 틀릴 수 있다는 사실을 감추면 한 번 틀렸을 때 서비스
전체를 신뢰하지 않게 된다. 그래서 오차, 기준일, 추정 여부, 공식 전망과의 차이를 항상
같은 자리에 적는다.

## 9쪽 — 사업성: 확장 경로

*겨냥: 사업성 20점*

**1단계 — 농업인 (현재)**
회원가입 없이 우리 지역 물 사정과 오늘 할 일을 확인한다. 기기에 코드 2개만 저장하므로
개인정보 부담이 없고, 웹은 링크 하나로 즉시 쓸 수 있다.

**2단계 — 수리계·마을 단위**
같은 대표 저수지를 공유하는 이용자들이 **같은 화면을 근거로** 관개 순번을 논의한다.
지역을 여러 개 등록하고 순서를 바꿀 수 있어 수리계장이 담당 저수지를 함께 관리할 수 있다.
확장 지점: 저수지별 알림 구독, 순번 공유 링크.

**3단계 — 지사·지자체**
시군 단위 비교(주변 지역 비교 카드)가 이미 들어 있다. 확장 지점: 관할 저수지 일괄 조회,
단계 악화 지역 자동 보고, 기존 물관리 시스템과의 데이터 연계.

**운영 비용이 낮다.** 공공데이터는 무료이며, 예측은 서버에서 계산하고 LLM은 캐시·예산
가드로 상한이 고정돼 있다. 사용자가 늘어도 비용이 선형으로 늘지 않는 구조다.

| 확장 축 | 근거 |
|---|---|
| 지역 확대 | 예측은 154개 시군 전체에서 검증, 추정은 70개 시군 적용 (확대 가능) |
| 플랫폼 확대 | 웹·Android가 하나의 OpenAPI 계약을 공유 → iOS 추가 시 서버 변경 없음 |
| 기능 확대 | 행동 카탈로그가 데이터라 새 단계·계절 행동을 코드 변경 없이 추가 |

## 10쪽 — 완성도·검증·한계

*겨냥: 완성도 10점 + 신뢰*

**구현 범위**

| 구분 | 내용 |
|---|---|
| 웹 | Next.js, Vercel 배포. 온보딩·지역 설정·메인·흐름 상세·정책 3종 |
| Android | Kotlin / Jetpack Compose. 서명 release APK, Android 8.0 이상 |
| 서버 | 버전 고정 공개 API 8개 (`/api/v1/*`), OpenAPI 계약이 단일 출처 |
| 데이터 | KRC 5종 정규화 스냅샷 + 검증 리포트를 저장소에 커밋 |

**검증**

| 항목 | 결과 |
|---|---|
| 자동 테스트 | 웹 739 · 계약 51 · LLM 59 = **849개 통과**, Android 단위 테스트 47개 파일 |
| CI 게이트 | 레이아웃·포맷·OpenAPI(strict)·lint·타입·테스트·빌드 + 문서 링크 검사 |
| 계약 일치 | 웹·Android가 같은 계약 픽스처로 같은 수치·단계·행동을 반환하는지 대조 |
| 배포 확인 | 라이브 API 실데이터 응답, 보안 헤더 6종, 서명 APK 해시 검증 |

**보안·개인정보**

- 회원가입·로그인 없음. 기기 저장은 시군 코드·시설 코드·동의 버전뿐.
- 주소 원문·검색어를 데이터베이스에 담지 않는다. 다만 호스팅(Vercel) 접속 기록에 IP와
  요청 URL이 남을 수 있다는 사실을 **정책 문서에 명시**했다.
- CSP·HSTS·nosniff·Referrer-Policy·frame 차단·Permissions-Policy(위치 차단) 적용.
- 로그는 허용된 필드만 남기는 구조화 로그(`source·status·fallback·requestId`).

**한계를 밝힌다**

1. 예측은 **참고용**이다. 공식 가뭄 예·경보가 우선이며 화면과 약관에 함께 적었다.
2. 지역 값 추정은 게이트를 통과한 **70개 시군에만** 적용한다. 나머지는 공표값 기준일을
   그대로 보여준다.
3. 저수지 방류·하류 안전 안내는 하지 않는다. 만수위 근접 시 **공식 재난 문자를 확인하라고
   안내**한다.
4. 도달 시점은 선형 외삽이며 강우 예보를 넣지 않았다. 추세가 바뀌면 값도 바뀐다.

**제출 후 유지** — 2026-09-10 발표심사까지 웹 URL·APK 설치 링크·환경변수를 변경하지 않는다.
